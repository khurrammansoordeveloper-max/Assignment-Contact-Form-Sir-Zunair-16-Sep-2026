17. One important security concept: escapeHtml()

Your project has this function:

function escapeHtml(text) {
    const map = {
        '&': '&amp;',
        '<': '&lt;',
        '>': '&gt;',
        '"': '&quot;',
        "'": '&#039;'
    };

    return text.replace(/[&<>"']/g, function(m) {
        return map[m];
    });
}

Its purpose is to prevent user-entered text from being interpreted as HTML when you insert it using innerHTML.

You can tell your teacher:

escapeHtml() converts special HTML characters into safe entities to reduce the risk of HTML injection.

That's a good answer.

In your project, we use switch because the function needs to perform different actions depending on which button/action was selected.

Your code is:

function handleHeaderClick(actionName) {
    const outputDiv = document.getElementById('action-output');

    switch(actionName) {
        case 'TEST':
            outputDiv.textContent = "Status: Running system diagnostics test...";
            break;

        case 'EDIT':
            outputDiv.textContent = "Status: Click any member in the list to edit their record.";
            break;

        case 'SUBMIT':
            outputDiv.textContent = "Status: Data batch successfully SUBMITTED!";
            break;

        case 'NEXT':
            outputDiv.textContent = "Status: Navigating to NEXT module...";
            break;
    }
}

This is the exact pattern used in your uploaded project.

Think of switch like a menu

Your HTML has buttons such as:

<button onclick="handleHeaderClick('TEST')">TEST</button>

<button onclick="handleHeaderClick('EDIT')">EDIT</button>

<button onclick="handleHeaderClick('SUBMIT')">SUBMIT</button>

<button onclick="handleHeaderClick('NEXT')">NEXT</button>

When you click TEST, JavaScript receives:

actionName = "TEST"

Then:

switch(actionName)

asks:

"What is the value of actionName?"

It finds:

case 'TEST':

and executes that code.

Why not use many if...else statements?

You could write the same thing like this:

if (actionName === "TEST") {
    // TEST
}
else if (actionName === "EDIT") {
    // EDIT
}
else if (actionName === "SUBMIT") {
    // SUBMIT
}
else if (actionName === "NEXT") {
    // NEXT
}

That works.

But when you have one variable with many possible fixed values, switch can make the code easier to read.

switch is basically:
             actionName
                  ↓
        ┌─────────┼─────────┐
        ↓         ↓         ↓
       TEST      EDIT     SUBMIT
        ↓         ↓         ↓
      Action    Action    Action
What does case mean?
case 'TEST':

means:

If actionName is "TEST", execute this code.

For example:

case 'EDIT':
    outputDiv.textContent = "Click any member to edit.";

means:

If actionName is "EDIT", show this message.

What does break mean?

This is very important.

case 'TEST':
    outputDiv.textContent = "Testing...";
    break;

break means:

Stop the switch here.

Without break, JavaScript can continue executing the following cases.

So normally you write:

case 'TEST':
    // code
    break;
